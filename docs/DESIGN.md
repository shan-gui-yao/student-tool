# 设计说明

记录这个项目里几个不太显然的决定，以及走过的弯路。

---

## 一、定位：一条流水线，不是一个工具箱

最早的需求清单是六个功能：录音、总结、导图、翻译、写作、PPT。如果把它们平铺在首页，用户打开后不知道该点哪一个——这是「工具箱」的典型失败。

所以产品只保留一条主线：

```
一节课进来 → 录音 → 转写 → 分段摘要 → 思维导图 → 复习/考点/PPT/提纲
```

其余功能挂在这条线的下游，或者按科目下沉到二级页。首页回答的问题只有一个：**我要开始录了，点哪**。

## 二、三个关键取舍

### 1. 摘要用本地算法，而不是调大模型

理由不是"技术洁癖"，是可用性：

- 教室网络经常不可用，调 API 会直接卡住整条链路
- 一次 90 分钟的课，摘要要能立刻出来，不能等
- 作业场景里，学生没有 API Key

代价是摘要只能**抽取**（从原句里挑），不会改写、不会归纳出新观点。这一点在 README 的「已知限制」里写明了。

### 2. 单文件 HTML，而不是现代前端工程

整个应用是一个 3500 行的 `index.html`，内联 CSS 和原生 JS，没有任何依赖和构建步骤。

好处是交付形态极简——双击就能用，拷给别人不会因为少一个 `node_modules` 跑不起来。
代价是可维护性差：没有模块化、没有类型检查、改一处要靠人肉搜索。

对一个自包含的小工具来说，这个交换是划算的。

### 3. 没有数据时显示演示内容，但必须标注

第一次打开的页面如果是空白，用户不知道这东西能干什么。
但如果直接把演示数据伪装成"你的数据"，那就是欺骗。

做法是：自动加载一份模拟课堂，同时顶部挂一条琥珀色横幅，写明"这是演示数据"，并在左侧把输入源高亮到"粘贴文本"，让用户看到这些内容是从哪段文字来的。

## 三、关键词抽取：一个反例

最初的实现是纯 n-gram 统计：取 2–4 字的所有组合，按频次排序。

结果惨不忍睹。以一段讲「深度优先遍历」「广度优先遍历」的课为例，排在前面的词是：

```
度优先遍历    ← 跨词碎片：深|度优先遍历 和 广|度优先遍历 的公共部分
用邻接表      ← 把动词吃进来了
源最短路      ← 从「单源最短路」里截出来的
```

为了压掉这些碎片，最后叠了四层规则：

1. **学科词表加权**：命中常见术语（时间复杂度、最短路径、邻接矩阵…）时额外加分
2. **边界过滤**：以「的/了/用/把/这」等虚词开头或结尾的候选直接丢弃
3. **碎片剔除**：如果某个词几乎总是跟着一个更长的词一起出现（频次接近），它就不算独立词
4. **重叠去重**：与已选词有两个字以上重叠、且自身不在词表里的，丢弃

四层之后，同一段文字的关键词变成：

```
时间复杂度 · 单源最短路 · 邻接矩阵 · 邻接表 · 最短路径
Dijkstra · 遍历 · 数组 · 递归 · 队列
```

仍然不完美（中文没有分词就没法根治），但可用了。

## 四、摘要：每段挑一句

中文转写没有标点，按句号切会得到一整段。

最终做法是：按**时间间隔**和**累计字数**切段，然后在每段内部找出"命中关键词最多"的那一行原话。

- 时间间隔 > 14 秒 → 认为换了一个话题
- 单段累计 > 84 字 → 强制截断，避免一段吃掉整节课

早期版本把整段直接拼起来当摘要，读起来像流水账；改成挑一句之后，每段都变成一条能独立阅读的结论。

## 五、导图：三级树，最多五个分支

根节点是课名，一级是段落主题（取该段命中的关键词），二级是这段的其他关键词。

限制在 5 个分支、每个分支 2 个子节点，是因为再多人眼就散了；节点宽度随手写 SVG，超长文本截断加省略号。

## 六、PPTX：为什么自己写 OOXML

前端没有现成的 PowerPoint 库（pptxgenjs 有 800 KB，会破坏"零依赖"）。

做法是：

1. 用 python-pptx 生成一份**单页模板**
2. 把它的所有 OOXML 部件提取成 JSON（`tools/parts.json`）
3. 导出时只替换幻灯片 XML，再手写一个 **stored（不压缩）的 ZIP** 打包

其中 ZIP 只用实现 CRC32 + 本地头 + 中央目录 + EOCD 四段，约 60 行。
产物用 python-pptx 重新打开验证过：页数、文字、包结构都对。

模板里原本带着 python-pptx 默认模板的作者信息（`lastModifiedBy: Steve Canny`）和一张写着 "T/A/B" 的缩略图，导出时会跟着每个文件走；已经清空并移除。

## 七、桌面版：两个踩过的坑

1. **exe 所在路径不能含中文**。放在含中文的目录下启动，进程秒退、没有日志、没有报错；换成英文目录就正常。入口可以用中文快捷方式，但目录名必须是英文。
2. **`ELECTRON_RUN_AS_NODE=1`**。这个环境变量会让 `electron.exe` 退化成普通 Node，报 `Cannot find module 'electron'`。排查时容易误判成"Electron 没装上"。

## 八、没做的

- 数据不落盘：没有 localStorage / IndexedDB，关掉页面就没了
- 实时转写依赖浏览器自带的语音服务，网络环境差时不可用
- 翻译只有一个入口，没有实现
- 复习卡片不做遗忘曲线调度，只是顺序翻卡

这些都在 README 的「已知限制」里如实列着。
